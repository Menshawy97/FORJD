# Lane 3 — Privacy and health data (2026-09-25, at b1f006a)

### L3-1 — A queued workout or run is uploaded under the next account after sign-out
- **Severity:** blocker (as reported; verification pending)
- **Where:** `apps/mobile/src/auth/secureStorage.ts:144-162` (`clearSession`), `store/local-data.ts:1-36` (`clearLocalUserData`, not called on sign-out), `app/_layout.tsx:107-114` (`syncPendingSessions()` on auth and every foreground), `workouts/sync-sessions.ts:48-67`, `store/workout-session.ts:92,394-402,445-449` (`session_queue` has no user column); server `apps/api/src/workouts/workout-sessions.service.ts:56-77` (owner from the JWT).
- **Scenario:** A finishes a workout or run offline, signs out before it syncs; B signs in on the same phone; the next foreground drains A's queue under B's token. A's session (sets, weights, notes, run heart rate and calories collected under A's consent) becomes B's on the server, is removed from the local queue, and can feed B's leaderboard score.
- **Rule / ADR:** rule 15 spirit, ADR-043/050 (consented health data attributed to another account).
- **Suggested fix:** scope `session_queue` / snapshot / events by user id (or the whole local DB), refuse to drain rows from another user, and clear or drain-then-wipe on every sign-out.
- **Known gap?** escalates the roadmap's sign-out snapshot gap from a UI prompt to a silent server write.

### L3-2 — Account export omits run summaries, splits, heart rate and calories
- **Severity:** high · **Where:** `apps/api/src/users/account-export.service.ts:135-141,266-283`; `apps/api/src/workouts/workout-sessions.repository.ts:253-267` (no join to `workout_run_summaries` / `workout_run_splits`); schema `workouts.schema.ts:341-376`
- **Scenario:** `GET /users/me/export` returns runs without distance, moving time, splits, average HR or calories; `data-inventory.md:32-33` says they are exported. No route reads those tables at all.
- **Rule / ADR:** GDPR Art. 15/20 (export completeness), `data-inventory.md`.
- **Suggested fix:** read the run tables per session and include them in the session and export responses.
